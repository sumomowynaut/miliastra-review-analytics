# 方法论 · 06 交付物检查

> 数据交付 ≠ 文件生成。**文件生成了不等于能交付。**

## 坑：交付前才发现文件坏了

出现过两次：
- Excel 生成后中文表头变成乱码（编码问题）
- 看板 HTML 里引用的数据路径写死，拿到别的机器打不开

**规则：交付前必须"实际打开验证"，不能只看文件存在。**

## Excel 检查清单

自动校验（`verify_excel`）：

- [x] 能正常打开（用 openpyxl 重新 load 一次）
- [x] 中文无乱码（表头抽检）
- [x] 工作表数量与预期一致
- [x] 每张表非空

需要人工确认：

- [ ] 行数与数据条数一致
- [ ] 关键指标与源数据交叉核对
- [ ] 关键列宽度合适、长文本自动换行
- [ ] 日期格式统一为 `YYYY-MM-DD HH:MM`（本项目存字符串，便于筛选排序）
- [ ] 百分比列表头标注 `(%)`、单元格存数值（如 `90.6`，不是 `0.906`）

```python
issues = verify_excel(path)
assert not issues, issues
```

## 脱敏检查（如果对外发布）

> **本项目的工具已强制执行这一条**：默认产出（Excel / 看板 / analysis.json）
> 全部脱敏，并在生成后自动做产出自检。需要真实身份时显式加 `--keep-identities`。
> 详见 `src/analyze.py` 的 `_scan_output_for_identities()`。

- [ ] 无真实 UID
- [ ] 无真实昵称
- [ ] 无 IP 属地
- [ ] `.gitignore` 排除了数据产出目录
- [ ] **评论正文是否为玩家原话已明确告知**（正文未脱敏，需要说明）

> ⚠️ 自检要**按字段查**，不要全文件搜子串 —— 昵称里混着 "404"、"。。。"
> 这类短串，它们天然出现在评论正文里，全局搜会产出上千条误报。
> 一个会误报的检查等于没有检查。

### ★ 行级 IP ≠ 聚合统计

| | 例子 | 性质 | 处理 |
|---|---|---|---|
| **行级 IP** | 这条评论来自广东 | 个人身份 | **必须移除** |
| **聚合统计** | 广东 232 条 | 不指向个人 | **可以保留** |

把两者一刀切会同时犯两个错：要么留了个人数据，要么把有用的地域分布功能删没了。

正确做法：**先脱敏行级 IP，再从脱敏前的原始数据单独算省份级聚合**，只输出计数。

> 踩过的坑：一度先清空 IP 再算分布，结果地域分布整个消失 ——
> 把"删个人信息"做成了"删功能"，还让已发布的案例无法复现。

**注意：Git 历史不可撤回。** 一旦 commit 过，删文件也没用 —— 必须用 `filter-repo` 重写历史。

```bash
git filter-repo --path data/ --invert-paths
```
