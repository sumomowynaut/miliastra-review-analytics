# 方法论 · 05 先验证再下结论

> 这条不是技术问题，是**工作方式**问题。但它是前面所有方法能否成立的前提。

## 真实记录

同一天里，犯了三次同类错误：

### 错误 1：长将问题"已修复"

**推理**：相关评论从 8 条降到 2 条 → 问题已修复。
**推翻**：次日新增 3 条"长将还是卡"。
**错因**：把短期波动当成趋势。

### 错误 2：1001 是新手号段

**推理**：几个 100x 开头 UID 的评论风格偏新手 → 1001 号段是新手。
**推翻**：样本只有 5 条。
**错因**：样本量不足以支撑结构性结论。

## 共同错因

**先下结论 → 再找证据 → 找不到就当验证通过。**

正确顺序是：**先列假设 → 找验证手段 → 拿到证据 → 才下结论。**

## 工作准则

### 1. 结论必须可推翻

写下结论时同时写下：**什么证据能推翻它？**

> "长将问题已修复"
> → 推翻条件：绝对量稳定低于 3 条/周 连续 4 周
> → 当前：3 条/2 周，不满足 → **不能下这个结论**

### 2. 区分三类陈述

| 类型 | 标注方式 | 例子 |
|---|---|---|
| 官方事实 | 附一手链接 + 原文 | 官方好评率 79.2% |
| 玩家陈述 | 注明"玩家称" + 原帖 | "热度算法一版调过4次" |
| 我的推断 | 注明"推断" + 置信度 | 热度含日衰减（推断，中置信） |

**三者混在一起 = 误导。**

### 3. 不确定就说不确定

"我没法从 201 个样本反推热度公式" 是合格的结论。
"热度大概等于游玩量 × 0.3" 是编造。

### 4. 记录每个被推翻的结论

```
2026-10-19  1001=新手号段  → 推翻（样本仅5条）
2026-10-19  长将已修复    → 推翻（次日新增反例）
```

**这份记录往往比结论本身更有价值** —— 它告诉读者哪些结论不可轻信。

### 5. 查一手资料，不依赖二手转述

**规则：涉及机制/规则的结论，必须找到原文链接。** 找不到就说"未找到官方披露"。

## 自检清单

写完报告后过一遍：

- [ ] 每个数字都能追溯到原始数据？
- [ ] 每个结论都写了推翻条件？
- [ ] 官方事实 / 玩家陈述 / 我的推断分开标注了？
- [ ] 有没有编造的引用？
- [ ] 被推翻过的结论记录在案？
